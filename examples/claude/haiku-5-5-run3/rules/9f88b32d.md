# Project rules

Write clear code and keep changes small.

## Implementing a function from its docstring

- Write the whole file. Import every name you use (islice, zip_longest, count, deque, itemgetter and so on) at the top, and never leave `raise NotImplementedError` behind.
- Match the docstring examples exactly, including the last partial group, fill values and what happens at the end of the input.
- Check arguments the way the standard itertools functions do: a size, step or width that is negative, or zero where zero makes no sense, raises ValueError; an option outside its documented choices raises ValueError; a value that must be iterable but is not raises TypeError. Any other argument, such as a count that is only compared against results, accepts every value and returns what the docstring describes for it, with no raise.
- Do these checks before returning a generator, not inside it, so they run at call time.
- When inputs must line up (a strict mode, rows of different lengths), raise ValueError instead of silently truncating.
- Prefer itertools building blocks (islice, chain, tee, zip_longest) over index arithmetic.
